# エージェントごとにできること

[English](agents.md) · [README](../README.ja.md)

1回のインストールで2つのランチャーが入ります。ワークステーションへの到達方法（マウント、共有SSH接続、レジストリ、ロック）はすべて共通で、違うのは起動するエージェントと、そのエージェントが公開している機能だけです。

| | `claudefws`（Claude Code） | `codexfws`（Codex CLI） |
| --- | --- | --- |
| マウント・共有SSH接続・終了時の解放 | あり | あり |
| `afws-run`・`afws-lock`・`afws-umount` | あり | あり |
| `afws-peers`にホストとディレクトリが並ぶ | あり | あり |
| エージェント自身が知っているセッション名 | あり（`--name`） | なし |
| `afws-peers`の状態列（`busy`/`idle`/`waiting`） | あり | なし（`-`） |
| 他セッションから名前指定でメッセージ | あり（`SendMessage`） | なし |
| ローカル実行に`[mac]`の印が付く | あり | なし |
| バックグラウンドセッション（`--bg`） | あり | なし |
| 追加のローカルディレクトリ（`AFWS_ADD_DIR`） | あり | あり |

`AFWS_ADD_DIR`を両方「あり」としているのは、外から見た振る舞いが同じだからです。内部で必要な指示は異なります。Claude Codeはファイルツールを作業ディレクトリに限定するため`--add-dir`で追加ディレクトリを渡し、Codexはワークスペース外を既に読めるのでそれらをサンドボックスのwritable rootsとして追加します。ランチャーが翻訳するので、利用者が設定するのは1つの変数だけです。

ただし、ローカルディレクトリを**読む**だけならどちらのエージェントでも不要です。シェルコマンドはアカウントが届く範囲に届き、Claude Codeはセッション中に`/add-dir`も受け付けます。この変数が意味を持つのは、毎回同じディレクトリを使う場合と、ワークスペース外への書き込みが必要な場合です。後者はCodexでは起動時にしか決められません。

残りの差は設計上の選択ではなく、各CLIが提供している機能の差です。Codex CLI 0.154.0で実測した結果に基づきます。

- **起動時にセッション名を指定するフラグがない。** そのためレジストリ上の名前は記録のためだけのもので、`afws-peers`での識別とロックの保持者表示には使えますが、Codex自身はその名前を知りません。名前が私たち側のものであってエージェントのものではないことを明示するため、Codexセッションは`fws-…`ではなく`cx-HOST-PROJECT-N`という名前にしています。
- **機械可読なセッション一覧がない。** `codex agents`はJSON出力のない対話的ブラウザなので、Codexセッションの生存はlauncherプロセスから判断し、状態は報告できません。`claude agents --json`はid・pid・statusを返すため、状態列を埋められます。
- **名前指定のメッセージ送信ができない。** `codex queue --thread <UUIDまたは正確なセッション名> --message TEXT`は存在し、本来これが適切な仕組みですが、起動時に名前を付けられないため宛先がありません。Codex CLIが名前指定のフラグを持てば、小さな変更で対応できます。
- **シェルのラッパーがない。** Claude Codeは`CLAUDE_CODE_SHELL_PREFIX`経由でシェルコマンドを実行するため、そこで`[mac]`を付けられます。Codex CLIには相当する仕組みがないので、Codexセッションではコマンドがローカルで実行されたことを示す印が付きません。代わりにセッションへの指示文で明示しています。

## 実際の影響

Codexセッションは、ワークステーションを保護する仕組みにはすべて参加します。同じホスト上の他セッションとマウントと認証済み接続を共有し、`afws-lock`を取得・尊重し、最後の利用者だった資源を終了時に解放します。同じワークステーション上のClaudeセッションからは`afws-peers`で見えるため、担当ディレクトリを避けられます。

できないのは、他セッションから質問されることです。Claudeセッション同士なら「8Bの学習は終わったか」を互いに解決できますが、Codexセッションには**あなたが**尋ねる必要があります。

## 併用する場合

Claudeセッションと Codexセッションが同じワークステーション、さらに同じディレクトリで作業することは妨げられません。マウントを共有するので同じSSHFS接続を通して同じファイルを見ており、GPUは`afws-lock`で直列化されます。ただしClaudeセッション同士の場合より注意が必要です。互いに会話できないため、連携に頼らず、ディレクトリで作業を分けるか、ロックを保持してください。

連携の仕組み自体は[複数セッション](sessions.ja.md)を参照してください。
