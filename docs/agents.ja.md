# エージェントごとにできること

[English](agents.md) · [README](../README.ja.md)

1回のインストールで2つのランチャーが入ります。ワークステーションへの到達方法（マウント、共有SSH接続、レジストリ、ロック）はすべて共通で、違うのは起動するエージェントと、そのエージェントが公開している機能だけです。

| | `claudefws`（Claude Code） | `codexfws`（Codex CLI） |
| --- | --- | --- |
| マウント・共有SSH接続・終了時の解放 | あり | あり |
| `afws-run`・`afws-lock`・`afws-remount`・`afws-umount` | あり | あり |
| `afws-peers`にホストとディレクトリが並ぶ | あり | あり |
| エージェント自身が知っているセッション名 | あり（`--name`） | あり（ランチャーの指示で共有） |
| `afws-peers`の状態列 | CLI由来の`busy`/`idle`/`waiting` | フック由来の`busy`/`idle` |
| 他セッションから名前指定でメッセージ | あり（Claudeの`SendMessage`） | あり（`afws-message`） |
| ローカル実行に`[local]`の印が付く | あり | なし |
| バックグラウンドセッション（`--bg`） | あり | なし |
| 追加のローカルディレクトリ（`AFWS_ADD_DIR`） | あり | あり |

`AFWS_ADD_DIR`を両方「あり」としているのは、外から見た振る舞いが同じだからです。内部で必要な指示は異なります。Claude Codeはファイルツールを作業ディレクトリに限定するため`--add-dir`で追加ディレクトリを渡し、Codexはワークスペース外を既に読めるのでそれらをサンドボックスのwritable rootsとして追加します。ランチャーが翻訳するので、利用者が設定するのは1つの変数だけです。

2つのエージェントで必要な理由は異なり、Claude Codeではほとんど必要ありません。`claudefws`ではワークスペース外のパスの読み取り・作成・編集を実際に試してすべて通ったので、そこではそのディレクトリのスキルやコマンドを読み込むかどうかにだけ効きます。`codexfws`では、ローカルディレクトリが書き込み可能になる手段です。Codexが書き込みをワークスペースに限定し、それを起動時に決めるためですが、この点はサンドボックスのプロファイルからの推定で、直接検証はしていません。

残りの差は各CLIの機能によるものです。Codex CLI 0.156.1で実測しました。

- **起動時にセッション名を指定するフラグがない。** ランチャーが`cx-HOST-PROJECT-N`というレジストリ名を指示文でCodexに伝え、最初のターンが始まった後でフックが実際のCodexスレッドUUIDと紐付けます。
- **機械可読なセッション一覧がない。** `codex agents`はJSON出力のない対話的ブラウザです。生存はランチャープロセスから、`busy`/`idle`と短い作業ラベルはフックから取得します。Claudeの状態は`claude agents --json`から取得します。
- **メッセージの経路が異なる。** `afws-message`がレジストリ名をCodexスレッドUUIDへ解決し、`codex queue`で送ります。作業中なら現在のターン終了後に処理されます。Claude同士は従来どおり`ListAgents`と`SendMessage`を使います。このツールにCodexからClaudeへ外部送信する経路はありません。
- **シェルのラッパーがない。** Claude Codeは`CLAUDE_CODE_SHELL_PREFIX`経由でシェルコマンドを実行するため、そこで`[local]`を付けられます。Codex CLIには相当する仕組みがないので、Codexセッションではコマンドがローカルで実行されたことを示す印が付きません。代わりにセッションへの指示文で明示しています。

## 実際の影響

Codexセッションは、ワークステーションを保護する仕組みにはすべて参加します。同じホスト上の他セッションとマウントと認証済み接続を共有し、`afws-lock`を取得・尊重し、最後の利用者だった資源を終了時に解放します。同じワークステーション上のClaudeセッションからは`afws-peers`で見えるため、担当ディレクトリを避けられます。

Codexセッションも最初のターン後なら名前で質問を受けられます。送信側には名前ではなく「8B学習をしているエージェント」のように作業内容で指定できます。送信側は必要な時だけ`afws-peers --json`を参照し、作業ラベル・ホスト・ディレクトリから一意に特定します。曖昧なら確認します。フックはセッション一覧をモデルの文脈には入れません。

## 併用する場合

ClaudeセッションとCodexセッションが同じワークステーション、さらに同じディレクトリで作業することは妨げられません。マウントを共有するので同じSSHFS接続を通して同じファイルを見ており、GPUは`afws-lock`で直列化されます。CodexはClaude側からもメッセージを受けられますが、CodexからClaude宛てにはこのツールでは送れません。共有ファイルの編集では引き続き作業を調整し、必要ならロックを使ってください。

連携の仕組み自体は[複数セッション](sessions.ja.md)を参照してください。
