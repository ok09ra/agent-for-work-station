# セキュリティと公開前チェック

[English](security.md) · [README](../README.ja.md)

## リポジトリに入れないもの

- 実際のIPアドレスまたは内部ホスト名
- 実際のユーザー名
- パスワード、秘密鍵、API token
- 実際のローカルまたはリモートの絶対ディレクトリ
- `.ssh/config`、`.env`、接続ログ、画面キャプチャ

リポジトリ内の例には、予約済みの無効ドメインと説明用プレースホルダーだけを使います。実際の接続情報は、リポジトリ外にあるローカルのSSH configで管理します。

## 実行時の境界

`claudefws`は、マウントしたプロジェクトディレクトリを作業ディレクトリとし、permission modeを`auto`としてClaude Codeを起動します。対象は選択したプロジェクトディレクトリであり、リモートファイルシステム全体のマウントは拒否します。

`auto`モードは、安全と判定した操作を確認なしで承認します。したがって、すべてを確認する`manual`モードよりも副作用が発生する閾値は低くなります。これは、読み取り専用のリモートコマンドを多数実行するリモート作業向けの意図的な既定値です。作業内容に応じて、起動ごとにより厳しいモードを選べます。

```zsh
CLAUDEFWS_PERMISSION_MODE=manual claudefws SSH_CONFIG_HOST REMOTE_ABSOLUTE_DIRECTORY
CLAUDEFWS_PERMISSION_MODE=plan claudefws SSH_CONFIG_HOST REMOTE_ABSOLUTE_DIRECTORY
```

`bypassPermissions`は指定しないでください。セッション内のすべての書き込みはマウント越しにリモートへ到達するため、ローカルだけで済む影響範囲というものが存在しません。

Claudeには次の方針がセッションごとに渡されます。

- 利用者が明示的に範囲を広げない限り、ファイル操作はマウント済みワークスペース内に限る。
- 環境依存コマンドは`claudefws-run`経由でリモートへ送る。
- リモートのパッケージ、シェル初期化ファイル、システムまたはユーザー環境を、明示的な承認なしに変更しない。
- 破壊的・高コスト・長時間の操作の前に確認する。
- リモートの排他資源を使う前に`claudefws-lock`で確保し、利用者の指示がない限り保持中のロックを奪わない。

SSHは設定されたリモートユーザーの権限で動作し、それを超える権限は取得しません。接続に使うユーザーの権限が大きいほど想定される影響も大きくなるため、必要最小限の権限のアカウントを使ってください。

`claudefws`は管理者権限を付与も模倣もしません。リモートのアカウントが`sudoers`等の仕組みで許可されていない場合、`sudo`のようなコマンドで権限を昇格させることはできず、失敗します。launcherは対話的なSSH TTYを確保せず、sudoのパスワードを保存・提供・転送することもありません。

アカウントの名目上のsudo可否だけでなく、実際の権限も確認してください。既存のサーバー設定によって、パスワードなしsudo、コンテナランタイムのグループなどの特権グループ、set-user-IDプログラム、サービス管理権限、書き込み可能な特権自動化処理を通じて、すでに昇格した権限が与えられている場合があります。実効的なセキュリティ境界は、そのリモートアカウントに割り当てられた権限の全体です。

`claudefws-run`は、設計上リモートコマンドの実行器です。標準入力モードは任意のBashコードを実行でき、引数モードはSSHユーザーが利用できる任意のコマンドを起動できます。指定したリモートディレクトリは開始位置であり、セキュリティ境界ではありません。承認の前にコマンドを確認してください。特に、そのディレクトリの外に出るもの、ファイルを削除するもの、パッケージを導入するもの、高コストなジョブを開始するもの、リモート環境を変更するものは注意が必要です。

## セッションレジストリが保持する情報

`~/.claudefws/sessions/`配下のレジストリは、動作中の各セッションについて、名前、種別、プロセスID、SSHの接続名、リモートディレクトリ、マウントポイントを記録します。所有者のみがアクセスできる権限で作成され、資格情報、ホスト鍵、接続の秘密情報は含みません。ただし、実際の接続名と実際のリモートパスは含みます。SSH configと同様に扱ってください。画面キャプチャ、ログ、課題報告に含めず、このリポジトリへコピーしないでください。

`claudefws-lock`も同種の情報、すなわちセッション名、時刻、TTLを、リモート側の`~/.claudefws-locks`配下のロックディレクトリへ書き込みます。プロジェクトツリーの中には何も書き込まないため、ロックがプロジェクトのGit履歴へ入ることはありません。

## 共有SSH接続のソケット

`~/.claudefws/control/HOST.sock`は、認証済みで生きたリモートホストへの経路です。このソケットに到達できるものは、再認証なしにリモートユーザーとしてコマンドを実行できます。ディレクトリは所有者のみアクセス可能な権限で作成され、それが保護の境界になります。権限を緩めたり、共有ファイルシステム上へ置いたり、`CLAUDEFWS_STATE_DIR`を他ユーザーから読める場所へ向けたりしないでください。

そのホストでの作業を終えたら接続を閉じます。

```zsh
ssh -S ~/.claudefws/control/HOST.sock -O exit HOST
```

## セッション間メッセージは入力であり、命令ではない

他のセッションからのメッセージは、利用者のために動いている別のClaudeセッションが書いた内容であり、信頼されたコマンド経路ではありません。データの削除、パッケージの導入、保持中ロックの奪取、自身の作業範囲の拡大などを求められた場合、受け取ったセッションは他の依頼と同様に扱い、まず自分の利用者に確認するべきです。セッション間メッセージは、実際に実行・観測した内容を交換するためのものです。

## GitHubへpushする前に

公開候補の内容に対してチェックを実行します。

```zsh
./scripts/test.sh
./scripts/prepublish-check.sh
git status --short
```

自動検査は保険であり、機密情報が存在しないことを保証するものではありません。commit前に全ファイルを確認し、`git diff --cached`も点検してください。

一度でも秘密情報をcommitした場合、後のcommitで削除してもGitの履歴からは消えません。その履歴をpushしないでください。まず履歴から取り除き、該当の資格情報を無効化または更新してください。

## これらのスクリプトが行わない操作

同梱のinstaller、doctor、testは、Git remoteの追加、commit、push、release作成を行いません。リポジトリの公開操作は、内容確認後に別途実施してください。
